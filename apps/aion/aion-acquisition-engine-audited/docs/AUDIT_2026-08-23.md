## Hallazgos corregidos

| Prioridad | Hallazgo                                                                                            | Corrección aplicada                                                                                                                          |
| --------- | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Alta      | El intake público permitía intentar marcar un lead como hot.                                        | El contrato público ya no acepta `isHot`; el servidor lo fija en `false`.                                                                    |
| Alta      | Un ID incremental de nicho era enumerable en el intake público.                                     | Se añadió `publicKey` aleatoria y única; el endpoint público devuelve solo metadatos mínimos.                                                |
| Alta      | Las reglas clonadas podían conservar una referencia al template de origen.                          | El clonado crea un mapa de IDs y reasigna cada regla al template nuevo correspondiente.                                                      |
| Alta      | El callback programado podía procesar tareas de todos los nichos.                                   | El callback se limita a los nichos cuyo `scheduleCronTaskUid` coincide con el `taskUid` autenticado.                                         |
| Alta      | Las tareas vencidas se consultaban antes de aplicar todos los controles de consentimiento y estado. | La selección de tareas exige consentimiento concedido, ausencia de opt-out y de revisión humana, y una etapa no terminal.                    |
| Media     | Límite de body de 50 MB sin carga de archivos.                                                      | El límite se redujo a 256 kB para JSON y formularios URL-encoded.                                                                            |
| Media     | La consola detectó claves de navegación duplicadas y una query interna que devolvía `undefined`.    | Las claves de menú son únicas y la query devuelve `null` de forma explícita cuando el nicho no existe.                                       |
| Media     | Vulnerabilidades transitivas de producción.                                                         | Se actualizaron AWS SDK, tRPC, Axios, Drizzle, Express, Streamdown y NanoID; se eliminó el componente de gráficos no usado y su dependencia. |

## Garantías funcionales revisadas

Las reglas de negocio detienen la automatización si un lead no tiene consentimiento concedido, activa el opt-out, se marca como **needs human review**, o alcanza **Won** o **Lost**. El procesado de una tarea utiliza una reclamación condicionada por estado `scheduled`, por lo que llamadas repetidas no deben registrar el mismo follow-up dos veces cuando la base de datos confirma una sola fila afectada.

El intake público registra `consentAt` y `consentSource`. Incluye una clave de nicho no enumerable, un campo honeypot y un límite en memoria de seis solicitudes por IP y clave pública cada diez minutos. En hosting autoscale el límite se aplica por instancia, por lo que para campañas de alto volumen sigue siendo necesario añadir un límite distribuido o CAPTCHA gestionado.
